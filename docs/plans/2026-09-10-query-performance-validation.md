## 本地性能对照

对照基线为提交 `7ba46dcbf6a9848175561ccda0e4376f3cffe66d`。结果来自同机本地 TCP 服务与受控延迟，不是公网或 QQ 端到端指标。

| 场景 | 基线 | 改造后 |
| --- | --- | --- |
| 收齐 XML 后服务器继续保持连接，5 次中位数 | 404.517 ms | 0.494 ms |
| 目标延迟 50 ms，另一服务器延迟 700 ms | 整批完成 715.144 ms | 目标回复 59.444 ms |
| 1001 条缓存、200 次目标查询的回复构造 P95 | 未测 | 0.865 ms |

复现方式：

```bash
python -m tests.benchmark_warband --baseline-ref 7ba46dcbf6a9848175561ccda0e4376f3cffe66d
```

不同机器及后台负载会产生波动；优化收益主要来自消除人为等待和不再等待无关服务器，不承诺固定倍数。

## 有限公网核查

只请求官方目录和两台默认固定端点，没有发起全网探测。

- 官方 HTTPS 列表：成功解析 276 个有效端点，一次复测耗时 0.818 秒。
- 默认 7240 端点：返回 CN_YJMD_X1，单次耗时 1.650 秒。
- 默认 7242 端点：返回 CN_YJMD_X2，单次耗时 2.067 秒。

首次公网核查发现官方响应含合法重复 HTTP 头，新解析器最初过度拒绝。补充离线复现后，仅对正文分帧头检查冲突，允许其他重复头；针对性测试及官方接口复测均通过。另修复了缺少服务器名称的 XML 被误认为有效结果的问题。
